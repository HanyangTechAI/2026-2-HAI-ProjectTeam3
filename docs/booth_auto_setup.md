# 촬영 버튼에서 4컷·QR까지 연결하기

> 이 문서는 최초 HAI 연동 v1 설치 기록이다. 현재 Runpod 상대 연령·자동 영수증 변경은 [최신 적용 안내](booth_ui_qr_upgrade.md)와 [작업 인계](booth_handoff_20261126.md)를 먼저 확인한다. 이미 v1을 설치한 장치에 이 설치기를 다시 실행하지 않는다.

## 범위
- 기존 라즈베리파이 포토부스에 자동 처리 버튼을 추가한다.
- 기존 원본 촬영·저장·인쇄 기능과 좌우반전은 유지한다.
- 촬영 요청에 동의한 경우에만 사진을 촬영해 HAI로 보낸다.
- HAI의 실제 나이 추정·FADING 처리 결과를 받아 화면에 표시한다.
- 모의 결과나 이전 사람의 결과로 대체하지 않는다.
- 완성된 사진 다운로드 링크를 담은 QR을 라즈베리파이가 생성한다.
- AI 결과는 자동 인쇄하지 않는다. 기존 인쇄 버튼은 원본 촬영용이다.

## 설치 전
- HAI에서 app/fading_booth_api.py가 실행 중이어야 한다.
- 라즈베리파이의 http://127.0.0.1:18000/health 응답이 photobooth-fading이어야 한다.
- 맥의 HAI 포트 전달과 SSH 원격 포워딩을 유지한다.
- 라즈베리파이에 앞서 만든 capture_frame, capture_busy, camera_lock이 있는 촬영·저장 코드가 필요하다.

## 라즈베리파이 설치
1. tools/install_booth_auto.py를 라즈베리파이에 복사한다.
2. /home/photobooth/photobooth/env/bin/python -m pip install requests==2.32.5 qrcode==8.2
3. 같은 Python으로 install_booth_auto.py를 실행한다.
4. 성공한 경우에만 sudo systemctl restart photobooth.service
5. systemctl is-active photobooth.service가 active인지 확인한다.
6. /api/booth/health를 확인하고 웹 화면을 새로고침한다.

설치 프로그램은 문법과 기존 구조를 확인하고 원본을 백업한 뒤 교체한다.
동일 수정이 이미 적용됐다면 중복 설치하지 않는다. 서비스를 임의로 시작·종료하지 않는다.
복구할 때는 설치 시 출력된 백업 파일을 app.py로 복사하고 서비스를 재시작한다.
백업 복구 전 현재 코드도 별도로 보관한다.

## 동작 및 개인정보
- 웹 화면에서 성별 조건과 사진 전송·저장 동의를 선택한다.
- 3초 카운트다운 이후에만 촬영 요청을 보낸다.
- 생성 중 중복 촬영은 화면과 라즈베리파이 양쪽에서 막는다.
- 화면을 새로고침해도 같은 탭은 작업 상태를 다시 확인한다.
- 타임아웃이 나도 자동으로 생성 요청을 재전송하지 않는다.
- QR은 라즈베리파이의 LAN IP와 추측하기 어려운 작업 식별자로 만든다.
- 결과·QR 링크는 완성 후 1시간 동안만 제공한다.
- 링크 만료는 파일 삭제가 아니다. HAI와 라즈베리파이 원본·결과는 자동 삭제하지 않는다.
- 파일은 ~/Pictures/ai_booth/auto/에 보관되며 Git에 넣지 않는다.
- 같은 와이파이에서도 무선 단말 격리 설정이 있으면 휴대전화 접속이 막힐 수 있다.
- IP가 바뀌면 기존 QR이 작동하지 않을 수 있으므로 시연 중 네트워크를 유지한다.
- 잘못된 인터페이스를 선택할 경우 서비스 환경 변수 BOOTH_PUBLIC_BASE_URL에 실제 LAN 접속 주소를 설정한다.
- 로그인 없는 내부 시연용이다. 라즈베리파이나 HAI 포트를 외부 인터넷에 공개하지 않는다.

## 현장 확인 필요
- 실제 카메라 촬영·고해상도 전환·좌우반전.
- HAI 실모델 요청·응답과 실제 생성 대기 시간.
- 휴대전화 QR 스캔과 사진 다운로드.
- 기존 원본 촬영·인쇄 보존 여부.

로컬 자동 검사는 합성 이미지와 가짜 HAI 응답을 이용한다. 실제 GPU·웹캠·프린터 시험을 대신하지 않는다.
