# 현장 수령 검증 카드

**현재 조건:** 추정 나이를 정수로 만든 후 −10·+10·+20년 목표로 세 장을 편집한다. 편집 목표만 3~90세로 제한하고, 두 번째 칸은 현재 원본이다. 부스 내부 검증 동의와 포스터·영상 공개 동의를 구분한다. 아래 현장 표는 **기록 양식**이지 성공 기록이 아니다. 사진, QR 원본, 실제 다운로드 URL은 공개 Git에 넣지 않는다.

### 한 요청의 계약: 추정 27세

| 경계 | 입력 → 출력 |
|---|---|
| 태블릿 → Pi | 버튼·프롬프트 조건 → 카운트다운 후 웹캠 JPEG 1장과 Pi `job_id`. Pi가 JPEG와 조건을 `POST /api/fading/fourcut`으로 전송한다. |
| 나이 모델 → 서버 | JPEG → 추정 실수 27.0 → `booth_slots()`에서 반올림한 출발값 27. `target_ages(27)`에서 편집 목표 `[17,37,47]`을 한 번만 구한다. |
| 서버 → FADING | `--age 27 --targets 17 37 47` → 역변환에서 나온 원본 크롭·latent·단계별 임베딩 한 세트. 세 번의 편집이 같은 역변환 결과를 사용한다. |
| 합성 → Pi | `past_17.png`, `current.png`, `future10_37.png`, `future20_47.png` → 라벨이 있는 RGB 2×2 PNG 한 장. `X-Job-Id`, `X-Estimated-Age`, `X-Initial-Age`, `X-Target-Ages`가 같은 응답에 온다. |
| Pi → 관객 | Pi가 결과 바이트를 Pi ID로 저장하고 상태에 GPU ID를 연결한다. 화면·인쇄는 현재 표시한 **Pi ID**를 사용하며, QR은 `/result/<같은 Pi ID>?download=1`을 가리킨다. GPU ID는 서버 기록 대조용이다. |

서버 기록은 `~/.cache/booth-auto/<GPU ID>/metadata.json`(실행 인자·슬롯·시간), `frames/settings.json`(생성기가 사용한 값), `fourcut.png`에서 대조한다. 나이 계산·서버 인자·라벨·파일 선택은 모델 없이 `python -m pytest -q tests/test_fading_fourcut.py`로 재현할 수 있다. GPU 서비스가 실행 중이면 Pi 테스트 환경에서 `BOOTH_GPU_TEST_PORT=8000 BOOTH_GPU_TEST_IMAGE="$PHOTO" BOOTH_GPU_TEST_GENDER="$GENDER" python -m pytest -qs tests/test_booth_gpu_delivery.py`로 촬영·인쇄 하드웨어만 모의한 전체 경로를 확인한다.

### 상대 목표에서 확인한 범위 (2026-11-25)

RTX 4090에 저장된 `skimage` 우주비행사 사진을 직접 POST한 결과: HTTP 200, 추정 23.6750 → 출발 24 → 목표 `[14, 34, 44]`, 총 64.9초. 실제 35단계·보정 상한 5회·self 0.70·seed 0. 응답은 1024×1112 컬러 PNG이며, 각 타일은 해당 슬롯 파일과 픽셀 단위로 일치했다. 같은 사진의 별도 요청에서 모의 Pi 촬영 → 실제 GPU → 화면용 PNG까지 63.8초, 모의 프린터 비트맵의 QR 해독과 동일 PNG 다운로드까지 64.5초였다. 영수증 사진 영역도 화면 PNG의 인쇄용 변환과 일치했다. 두 요청 시간은 별도 측정이며 실물 수령 시간은 아니다. 육안상 34세와 44세 차이는 작아 10년 간격 식별 품질은 미확정이다.

같은 `skimage.data.astronaut` 사진을 쓴 내부 기술 검증이다. 두 실행은 시작·종료 시점이 달라 시간 차를 중계·인쇄 비용으로 해석할 수 없다. 모델 선정용 촬영본이나 포스터·영상 이미지로 사용하지 않았다. 부스에 탑재한 FADING은 **공개 가중치 추론**이고, 팀 학습 Age LoRA와의 비교는 적격 촬영본과 비공개 어댑터를 복원하기 전까지 미측정이다.

이번 서버에서 검증한 API 시작 예시(SSH 전달 대상 포트와 일치시킨다):

```sh
cd /workspace/hai/branches/booth-delivery
umask 077
PYTHONPATH="$HOME/.cache/fading-legacy:$HOME/.cache/fading-web" \
TORCH_FORCE_WEIGHTS_ONLY_LOAD=1 HF_HUB_DISABLE_TELEMETRY=1 HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
  /venv/main/bin/python -m uvicorn app.fading_booth_api:app --host 127.0.0.1 --port 8000
```

이는 이 서버에 복원한 전용 라이브러리·가중치 캐시를 전제로 한다. Pi에는 이 작업본의 `raspi/photobooth_app.py`를 `photobooth.service`가 실제 실행하는 경로에 배포하고, `PUBLIC_HOST`에 휴대폰에서 접근 가능한 Pi의 행사망 주소(포트·스킴 제외)를 설정한 뒤 서비스를 재시작한다. 자동 삭제가 없으므로 촬영 전에 결과 보관 기한·접근 범위를 고지한다.

## 1. 실제 요청이 멈출 때만: 어느 구간까지 같은 사진이 통과하는가?

동의받은 단일 얼굴 JPEG 한 장을 정해 바이트와 성별 조건을 그대로 유지한다. GPU 서버의 로컬 API → Mac의 GPU 포트 전달 입구 → Pi의 중계 입구 순서로, 앞 단계가 끝난 후 한 번씩 실행한다. 다음 단계에선 `BASE`만 해당 장치의 실제 전달 주소로 바꾼다. 기본 GPU 포트는 8000, 기본 Pi 중계 포트는 18000이다. Mac 포트는 현장 설정을 사용한다. 행사망에 GPU API를 직접 공개할 필요는 없다.

```sh
# 장치마다 BASE, PHOTO, GENDER를 설정한 뒤 실행. 받는 파일은 비공개 임시 폴더에 둔다.
umask 077
RUN=$(mktemp -d)
curl --fail --max-time 10 "$BASE/health"
curl --connect-timeout 10 --max-time 650 --silent --show-error \
  -D "$RUN/headers" -o "$RUN/response" \
  -w 'http=%{http_code} connect_s=%{time_connect} first_byte_s=%{time_starttransfer} total_s=%{time_total}\n' \
  -F "file=@$PHOTO;type=image/jpeg" -F "gender=$GENDER" "$BASE/api/fading/fourcut"
file "$RUN/response"
```

성공은 health 200만이 아니라 **실제 POST 200, PNG 네 컷, `X-Job-Id`와 `X-Processing-Seconds`**다. 동일 JPEG의 별도 POST들은 서로 다른 생성 작업이므로 출력 해시가 같아야 하는 것은 아니다. 422면 얼굴 수·입력을, 409면 앞 작업 완료 여부를, 5xx면 GPU 작업 로그를 먼저 확인한다. GPU 단독이 실패하면 중계 장애로 판정하지 않는다. GPU는 성공하고 Mac 또는 Pi에서만 실패하면 처음 실패한 전달 구간·타임아웃을 기록한다. `curl`의 시간은 그 장치에서 API 응답까지의 시간일 뿐 관객 수령 시간이 아니다.

## 2. 실제 촬영으로 3회 연속 확인

1. 행사 Wi-Fi에서 태블릿으로 Pi UI를 열고 **서로 다른 촬영본**을 사용한다. 시작 버튼을 누를 때 타이머를 시작한다. 왼쪽 위부터 행 우선으로 과거 편집본, 현재 원본, 가까운 미래 편집본, 먼 미래 편집본인지, 각 나이가 해당 촬영의 서버 기록과 같은지 확인한다.
2. 결과 화면의 인쇄를 한 번 누른다. 다시 촬영하지 않아야 하며 **하나의 영수증**에 방금 본 네 컷과 읽을 수 있는 QR이 나와야 한다. 프린터 전송 응답만으로 성공 처리하지 않는다.
3. 태블릿이 아닌 휴대폰으로 **종이에 인쇄된 QR**을 스캔한다. Pi `result/<job_id>` 주소의 식별자가 태블릿 결과와 같고, 같은 컬러 PNG가 열리고, 네 컷 내용·순서가 종이와 일치할 때 타이머를 멈춘다. 전화가 Pi 주소로 접속하지 못하면 행사 AP의 단말 격리와 QR 호스트·포트를 확인한다.
4. 연속 성공 횟수와 실패한 시도도 남긴다. 별도로 얼굴 없음·여러 명에서 재촬영 안내, 두 번 누를 때 중복 인쇄 방지, 서버 지연·프린터 오류 후 재시도를 확인한다. 영상은 동의받은 한 작업의 촬영부터 휴대폰 열기까지 담고 사전 생성 화면은 표시한다.

| 시도 | 작업 식별자(내부용) | 네 컷·인쇄·폰 일치 | 시작→수령(초) | 실패 지점/재시도 |
|---|---|---|---:|---|

## 3. 포스터에 붙일 자료

- [시스템 구성도](poster/one-capture.svg) 캡션: “한 번 촬영한 사진에서 과거·현재·두 미래를 구성한다. 흑백 영수증과 휴대폰 컬러 PNG는 같은 작업의 결과다.” **설계 그림**으로 표기한다.

## 4. 상대 연령 편집 품질 판정 (장비 불필요)

고정 10·30·50세에서의 35단계·보정 상한 5회·self 0.70 결과는 이 절의 합격 근거가 아니다. 기존 튜닝에 없던 사용 동의 사진을 연령대별로 고르고 프롬프트 조건, 시드와 크롭을 고정한다. API가 기록한 실제 목표와 시간을 남긴다. 독립 관찰자 두 명이 숫자를 가리고 (1) 원본과 같은 사람인지, 눈·입·자세가 보존됐는지, (2) 순서를 섞은 인접 쌍에서 더 나이 들어 보이는 쪽을 맞히는지 각각 판정한다. ‘구분 불가’와 형태 왜곡도 기록한다. 같은 상한을 쓴 쌍은 순서 평가에서 빼고 동률 사례 수를 별도 표기한다. 인물별 실패 예와 쌍별 정답/전체를 함께 보고한 뒤에만 설정을 채택한다. 0.70의 구분이나 동일인 유지가 약하면 같은 사진·조건에서 0.80과 맹검 비교한다.
