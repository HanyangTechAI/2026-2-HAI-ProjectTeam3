# 인물·배경 보존 수정과 실제 검증

2026-10-26. [단계별 Age LoRA 실험](age-lora-stages.md) 이후 사용자가 직접 확인한 잘못된 인물 선택, 배경 인물 뭉개짐, 배경·자세·옷·표정 변형에 대응했다. 단순 학습 연장 대신 추론 경로를 수정했다.

**배경과 주 인물 선택 문제는 고정 세트에서 개선했지만, 자연스럽고 충분한 연령 변환까지 해결한 완성품은 아니다.** 원본 보존과 연령 변화는 별도 성과로 보고한다.

## 중단 후 확인

사용자가 작업을 멈춘 뒤 재개를 요청했을 때 GPU 학습/추론 잔류 프로세스는 없었다. 보호 대상 파일27개, checkpoint100/200/300 전체 상태, 수정 전 생성 이미지400장의 SHA-256을 확인해 손상이 없음을 검사했다. `preservation_after_resume.json`에 기록했다. 기존 파일·사진·모델을 덮어쓰거나 학습을 다시 시작하지 않았다.

## 원인과 수정

### 주 인물 선택

이전640 검출기는 FFHQ의 큰 중앙 얼굴을 놓치고 작은 배경 얼굴만 찾기도 했다. "검출 결과가 하나라도 있음"은 성공 조건이 될 수 없다. `ffhq_12875`에서는16×17픽셀 배경 얼굴을 확대했고, `ffhq_29139`에서는 사진 가장자리의 다른 얼굴을 선택했다.

`gen.faces.FaceTools`는 이제640과320을 **항상 모두 검사**한다. threshold0.5는 낮추지 않았다. bbox/5점 landmark의 유효성, 보이는 면적, 중앙성, 중복 검출을 검사해 주 인물을 선택한다. 비슷하게 두드러지는 복수 인물이면 `ambiguous_primary_face`로 거절하며 임의로 고르지 않는다. 임베딩·crop·평가가 같은 선택 정책을 사용하고, 생성 중에는 `embedding(FaceEdit)`로 같은 선택을 재사용한다.

CPU 실제 검사에서 고정20장과 기존640 실패 validation230장 모두 주 얼굴 준비와 임베딩에 성공했다. 고정20장 중19장은 유효 얼굴1개,1장은 주 인물이 명확한 복수 얼굴이었다. 두 문제 사진의 중앙 인물 bbox를 이미지로 확인했다. 이것은 모든 사진에서의 정답률이나 인물 확인 결과가 아니다.

### 얼굴 영역 제한

이전에는 주변 배경이 포함된512 crop 전체를 img2img로 다시 그린 뒤 그 crop을 결과로 반환했다. 이제 기본 `PipelineConfig.preserve_background=True`에서 다음 순서로 처리한다.

1. 선택한 얼굴의 원본→crop affine 변환과 원본 RGB를 보관한다.
2. 작고 부드러운 얼굴 타원 마스크를 만들고 눈·입 중심 영역과 다른 검출 인물을 보호한다.
3. 기존 Realistic Vision V5.1의4-channel UNet을 Diffusers0.35.1 `StableDiffusionInpaintPipeline`으로 실행한다. 이 구현은 각 denoising step에서 마스크 밖 latent를 복원하는4-channel 경로를 지원한다. 별도 inpainting 모델을 다운로드하지 않았다.
4. 생성된 얼굴만 원래 좌표로 역변환해 합성한다. 원본 전체를 재보간하지 않으며, 최종 `source_mask==0` 픽셀은 원본 바이트를 그대로 사용한다. 결과 크기는 원본과 같다.

crop 반환이 필요한 기존 호출자는 `preserve_background=False`를 명시할 수 있다. 다만 주 얼굴 선택 정책은 수정된 정책이므로 과거 전체 결과의 정확한 재현 모드는 아니다. 수정 전 추론 소스는 `original_inference_source/`에 지문과 함께 따로 보존했다.

**기하학적 마스크는 의미 기반 피부 분할이 아니다.** 얼굴을 가로지르는 머리카락·안경·수염·천이 마스크 안에 있으면 바뀔 수 있다.29139의 작은 스카프 경계가 타원에 포함되는 사례도 기록했다. "모든 옷과 표정이 완벽히 동일"하다고 보장하지 않는다. 정확한 보존 보장은 저장한 마스크의0인 영역과 눈·입 보호 core에 한정된다.

## 실제 생성 검증

먼저 문제 사례와 유아/고령 입력6장으로30장을 생성했다. 이후 **원래 고정 validation20장과 목표8/25/45/65/80을 교체하지 않고**, FaceID-only와100-step LoRA의 두 조건으로200장을 생성했다. Test100은 사용하지 않았다.

seed42, strength0.6, steps25, CFG7.5, IP scale0.8, LoRA scale1.0은 유지했다. 변경한 것은 얼굴 선택·inpainting mask·원본 합성 및 보호 모드의 부정 프롬프트다. 따라서 과거400장과 **동일 프로토콜의 점수 비교가 아니다**.30장 pilot 전체 wall time은99.059초,200장 본 검증은591.426초였다.

| 항목 | 수정 FaceID-only | 수정 FaceID +100-step |
|---|---:|---:|
| 생성/저장 | 100/100 | 100/100 |
| 출력 얼굴 검출 | 100/100 | 100/100 |
| 생성/평가 오류 | 0 | 0 |
| ArcFace 평균 | 0.759741 | 0.806011 |
| 5점 Procrustes 참고 오차 | 0.016182 | 0.012469 |
| 목표8→80 InsightFace 참고값 평균 변화 폭 | 6.35 | 3.25 |
| 동기화 생성 호출 초/장 | 2.4068 | 2.4318 |
| 생성 호출 합 초 | 240.680 | 243.176 |

400장 실험의0.63/0.69와 위0.76/0.81을 직접 비교해 모델 개선이라고 주장하지 않는다. 검출 대상이 달라졌고 눈·입과 주변 원본 픽셀을 의도적으로 합성하므로 identity 수치는 구조적으로 높아진다. 높은 cosine이 자연스러운 노화 성공을 뜻하지 않는다. InsightFace 변화 폭 역시 실제 나이 정확도나 MAE가 아니며, 정식 MAE는 null이다.

### 픽셀 검증

- Pilot30/30장, 본 검증200/200장이 원본 크기를 유지했다.
- 본 검증200장 모두 저장된 얼굴 마스크 밖 변경 픽셀은 **0개**, 최대 채널 차이는 **0**이었다.
- 얼굴 영역 내부에는 실제 변경 픽셀이 존재한다. 원본 사진을 그대로 반환하고 생성 성공으로 기록한 것이 아니다.
- 같은 검사를 단색 생성 crop으로 CPU 고정20장 및 기존 실패230장에도 실행했다. 입력이 변하지 않음과 affine 일치를 확인했다.
- 이 보장은 파일에 저장된 수치 마스크에 대한 것이다. 배경/옷 전체의 semantic segmentation 검증으로 과장하지 않는다.

### 직접 본 결과

AI가 비블라인드로 pilot6장 및 본 검증의 주요 문제 사례를 검토했다. 사람 평가나 전체 자연스러움 점수로 보고하지 않는다.

- 12875는 이제 중앙 인물을 대상으로 편집하고, 뒤 인물·보도·초록 옷·자세를 유지한다. 이전의 전혀 다른 배경 얼굴 확대 결과가 사라졌다.
- 29139는 중앙 인물을 선택하고 옆 사람과 원래 구도를 유지한다. 큰 검은 crop 경계와 의도하지 않은 주 얼굴 교체를 피했다.
- 42525의 열린 입과 시선,69229의 뒤 인물,54548의 옷과 배경을 유지하는 방향으로 바뀌었다. 얼굴 피부 평활화·질감 및 부분 색조 변화는 남는다.
- 특히 유아와 아동 입력은 높은 목표 연령에서도 여전히 어려 보인다. 원본을 잘 보존하게 됐다는 이유로 연령 변환까지 성공했다고 판단하지 않는다.

## 검토에서 추가한 방어

독립 코드 검토에서 두 문제를 발견해 수정했다.

1. 주 인물로 선택하기에는 작은 다른 얼굴도 편집 마스크와 겹치면 보호해야 한다. 보호 bbox 수집을 선택용 최소 크기 조건보다 앞에서 수행하도록 수정하고17×17픽셀 겹침 회귀 테스트를 추가했다.
2. 복수 주 인물 때문에 선택을 거절해도 검출된 얼굴 수는 알려져 있다. 예외의 `selection_info.detected_count`를 평가 결과에 보존하고, identity/landmark는 null 및 오류 상태로 유지한다.

이 최종 방어 수정 이후 고정20장의 마스크가 생성 당시와 바이트 단위로 동일함을 확인했고, 저장된200장에 대해 픽셀 보존 검사를 다시 통과했다. 생성은 수정 직전 소스 지문으로 기록되어 있으며 원래 기록을 바꾸지 않았다. 새 edge-case 동작은 CPU 회귀 테스트로 확인한 것이지 추가 GPU 실행으로 위장하지 않는다.

최종 전체 테스트는 **111개 실행,109개 통과,2개 스킵**. 스킵은 기존 smoke ONNX/통합 얼굴 fixture 요구 테스트다. mask 회전·비정방형 입력·작은 주변 얼굴·눈/입 core·ambiguity 분모·inpainting API 연결 테스트를 포함한다.

## 남은 판단

배경과 주 인물 문제는 실제 고정 사진에서 재현하고 수정했지만, **현재 모델은 충분한 연령 변화를 내면서 자연스러움까지 유지하는 제품 수준이 아니다**.100-step은 기술적으로 유효한 후속 실험용 체크포인트이며 운영용 연령 모델로 채택하지 않았다. 추가700-step 학습으로 해결된다는 근거가 없어300에서 중단한다.

다음은 단순 더 오래 학습하기보다, 주 얼굴/가림 영역의 의미 기반 분할, 표정·구조를 유지하는 편집 conditioning, cross-age 학습 목적, 사람 평가를 각각 검증하는 작업이다. 배경 보존을 깨뜨려 나이 차이를 크게 보이게 하거나, 나이 변화가 거의 없는 결과를 높은 identity 점수만으로 성공 처리해서는 안 된다.

일부 초기 CPU 진단 스크립트 실패 로그와 별도 성공 재시도도 삭제하지 않았다. 모델 추론 성공과 진단 스크립트 실패를 구분한다. 기존 데이터·모델·100/200/300 및12-step 산출물은 그대로 보존했다.

```bash
# 기존 산출물은 덮어쓰지 않는다. 재실행시 새 output 경로를 지정한다.
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 OMP_NUM_THREADS=4 MKL_NUM_THREADS=4 TQDM_DISABLE=1 \
.venv/bin/python -m gen.compare_lora \
  --manifest outputs/age_lora_stages_20261026/preflight/manifest.json \
  --config outputs/age_lora_stages_20261026/recovery/config.json \
  --baseline \
  --checkpoint step100=outputs/age_lora_stages_20261026/train/checkpoint-100 \
  --insightface-reference --output outputs/age_lora_recovery_recheck
```
