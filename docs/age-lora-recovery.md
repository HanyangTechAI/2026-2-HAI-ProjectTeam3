# 인물·배경 보존 수정과 실제 검증 (2026-10-26)

2026-10-26의 수정·검증 기록이다. [단계별 Age LoRA 실험](age-lora-stages.md) 이후 사용자 사진 검토에서 확인된 잘못된 인물 선택, 배경 인물 뭉개짐, 배경·자세·옷·표정 변형에 대응했다. 학습 연장 대신 추론 경로를 수정했다.

**고정 세트에서 주 인물 선택이 개선됐고 보호 마스크 밖 변경 픽셀은 0개였다. 충분한 연령 변화와 자연스러움은 미해결로 남았다.** 원본 보존과 연령 변화는 별도로 평가했다.

## 기존 산출물 확인

실험 재개 전 GPU 학습/추론 잔류 프로세스는 없었다. 보호 대상 파일 27개, checkpoint 100/200/300 전체 상태, 수정 전 생성 이미지 400장의 SHA-256이 보존 기록과 일치함을 확인했다. 결과는 `preservation_after_resume.json`에 기록했다. 기존 파일·사진·모델은 보존했으며 학습은 재개하지 않았다.

## 원인과 수정

### 주 인물 선택

이전 640 검출기는 FFHQ의 큰 중앙 얼굴을 놓치고 작은 배경 얼굴만 찾기도 했다. 얼굴 검출과 의도한 주 인물 선택은 별도 확인이 필요했다. `ffhq_12875`에서는 16×17픽셀 배경 얼굴을 확대했고, `ffhq_29139`에서는 사진 가장자리의 다른 얼굴을 선택했다.

이 수정에서 `gen.faces.FaceTools`가 640과 320을 **항상 모두 검사**하도록 변경했다. threshold 0.5는 유지했다. bbox/5점 landmark의 유효성, 보이는 면적, 중앙성, 중복 검출을 검사해 주 인물을 선택한다. 비슷하게 두드러지는 복수 인물이면 `ambiguous_primary_face`로 선택을 거절한다. 임베딩·crop·평가가 같은 선택 정책을 사용하고, 생성 중에는 `embedding(FaceEdit)`로 같은 선택을 재사용한다.

CPU 실제 검사에서 고정 20장과 기존 640 실패 validation 230장 모두 주 얼굴 준비와 임베딩에 성공했다. 고정 20장 중 19장은 유효 얼굴 1개, 1장은 주 인물이 명확한 복수 얼굴이었다. 두 문제 사진의 중앙 인물 bbox를 이미지로 확인했다. 검증 범위는 해당 표본의 처리 결과이며, 전체 사진의 주 인물 선택 정답률이나 인물 신원 확인은 포함하지 않는다.

### 얼굴 영역 제한

이전에는 주변 배경이 포함된 512 crop 전체를 img2img로 다시 그린 뒤 그 crop을 결과로 반환했다. 수정 후 기본값 `PipelineConfig.preserve_background=True`의 처리 순서는 다음과 같다.

1. 선택한 얼굴의 원본→crop affine 변환과 원본 RGB를 보관한다.
2. 작고 부드러운 얼굴 타원 마스크를 만들고 눈·입 중심 영역과 다른 검출 인물을 보호한다.
3. 기존 Realistic Vision V5.1의 4-channel UNet을 Diffusers 0.35.1 `StableDiffusionInpaintPipeline`으로 실행한다. 이 구현은 각 denoising step에서 마스크 밖 latent를 복원하는 4-channel 경로를 지원한다. 별도 inpainting 모델을 다운로드하지 않았다.
4. 생성된 얼굴만 원래 좌표로 역변환해 합성한다. 원본 전체를 재보간하지 않으며, 최종 `source_mask==0` 픽셀은 원본 바이트를 그대로 사용한다. 결과 크기는 원본과 같다.

crop 반환이 필요한 기존 호출자는 `preserve_background=False`를 명시하도록 했다. 이 옵션에도 수정된 주 얼굴 선택 정책이 적용되므로 과거 전체 결과와 정확히 같지는 않다. 수정 전 추론 소스는 `original_inference_source/`에 지문과 함께 따로 보존했다.

**기하학적 마스크는 의미 기반 피부 분할과 다르다.** 얼굴을 가로지르는 머리카락·안경·수염·천이 마스크 안에 있으면 바뀔 수 있다. 29139의 작은 스카프 경계가 타원에 포함되는 사례도 기록했다. 픽셀 단위 보존 범위는 저장한 마스크 값이 0인 영역과 눈·입 보호 core에 한정되며, 옷과 표정 전체를 포함하지 않는다.

## 실제 생성 검증

먼저 문제 사례와 유아/고령 입력 6장으로 30장을 생성했다. 이후 **원래 고정 validation 20장과 목표 8/25/45/65/80을 유지하고**, FaceID-only와 100-step LoRA의 두 조건으로 200장을 생성했다. Test 100장은 사용하지 않았다.

seed 42, strength 0.6, steps 25, CFG 7.5, IP scale 0.8, LoRA scale 1.0은 유지했다. 변경한 것은 얼굴 선택·inpainting mask·원본 합성 및 보호 모드의 부정 프롬프트다. 따라서 과거 400장과는 **서로 다른 프로토콜의 결과**다. 30장 pilot 전체 wall time은 99.059초, 200장 본 검증은 591.426초였다.

| 항목 | 수정 FaceID-only | 수정 FaceID + 100-step |
|---|---:|---:|
| 생성/저장 | 100/100 | 100/100 |
| 출력 얼굴 검출 | 100/100 | 100/100 |
| 생성/평가 오류 | 0 | 0 |
| ArcFace 평균 | 0.759741 | 0.806011 |
| 5점 Procrustes 참고 오차 | 0.016182 | 0.012469 |
| 목표 8→80 InsightFace 참고값 평균 변화 폭 | 6.35 | 3.25 |
| 동기화 생성 호출 초/장 | 2.4068 | 2.4318 |
| 생성 호출 합 초 | 240.680 | 243.176 |

400장 실험의 0.63/0.69와 위 0.76/0.81의 차이에는 검출 대상 변경과 원본 픽셀 합성의 영향이 포함된다. 눈·입과 주변 원본 픽셀을 합성하므로 identity 수치가 높아지는 구조이며, 모델 자체의 개선 효과를 분리할 수 없다. 자연스러운 노화 여부는 cosine과 별도로 평가해야 한다. InsightFace 변화 폭은 나이 반응의 참고값이며 실제 나이 정확도나 MAE와 구분한다. 정식 MAE는 null이다.

### 픽셀 검증

- Pilot 30/30장, 본 검증 200/200장이 원본 크기를 유지했다.
- 본 검증 200장 모두 저장된 얼굴 마스크 밖 변경 픽셀은 **0개**, 최대 채널 차이는 **0**이었다.
- 얼굴 영역 내부에서는 변경 픽셀이 확인됐다.
- 같은 검사를 단색 생성 crop으로 CPU 고정 20장 및 기존 실패 230장에도 실행했다. 입력이 변하지 않음과 affine 일치를 확인했다.
- 검증 범위는 파일에 저장된 수치 마스크다. 배경/옷 전체의 semantic segmentation은 검증하지 않았다.

### AI 시각적 검토

AI가 비블라인드로 pilot 6장 및 본 검증의 주요 문제 사례를 검토했다. 별도의 사람 평가와 전체 자연스러움 점수는 없다.

- 12875는 수정 후 중앙 인물을 대상으로 편집하고, 뒤 인물·보도·초록 옷·자세를 유지한다. 이전의 배경 얼굴 확대 문제가 해소됐다.
- 29139는 중앙 인물을 선택하고 옆 사람과 원래 구도를 유지한다. 큰 검은 crop 경계와 의도하지 않은 주 얼굴 교체를 피했다.
- 42525의 열린 입과 시선, 69229의 뒤 인물, 54548의 옷과 배경을 유지하는 방향으로 바뀌었다. 얼굴 피부 평활화·질감 및 부분 색조 변화는 남는다.
- 특히 유아와 아동 입력은 높은 목표 연령에서도 여전히 어려 보인다. 원본 보존은 개선됐지만 연령 변화는 충분하지 않았다.

## 추가 수정과 회귀 검증

독립 코드 검토에서 두 문제를 발견해 수정했다.

1. 주 인물로 선택하기에는 작은 다른 얼굴도 편집 마스크와 겹치면 보호해야 한다. 보호 bbox 수집을 선택용 최소 크기 조건보다 앞에서 수행하도록 수정하고 17×17픽셀 겹침 회귀 테스트를 추가했다.
2. 복수 주 인물 때문에 선택을 거절해도 검출된 얼굴 수는 알려져 있다. 예외의 `selection_info.detected_count`를 평가 결과에 보존하고, identity/landmark는 null 및 오류 상태로 유지한다.

이 추가 수정 이후 고정 20장의 마스크가 생성 당시와 바이트 단위로 동일함을 확인했고, 저장된 200장에 대해 픽셀 보존 검사를 다시 통과했다. 생성 기록에는 수정 직전 소스 지문을 유지했다. 새 edge-case 동작은 CPU 회귀 테스트로 확인했으며 추가 GPU 생성은 수행하지 않았다.

당시 최종 전체 테스트는 **111개 실행, 109개 통과, 2개 스킵**. 스킵은 기존 smoke ONNX/통합 얼굴 fixture 요구 테스트다. mask 회전·비정방형 입력·작은 주변 얼굴·눈/입 core·ambiguity 분모·inpainting API 연결 테스트를 포함한다.

## 당시 결론과 한계

배경과 주 인물 문제는 실제 고정 사진에서 재현하고 수정했지만, **이 모델로 충분한 연령 변화와 자연스러움을 함께 확보하지는 못했다**. 100-step은 재로딩 가능한 후속 실험용 체크포인트로 보존했으며 운영용 연령 모델로 채택하지 않았다. 추가 700-step 학습의 효과를 뒷받침할 근거가 없어 학습은 300에서 중단했다.

당시 후속 과제로 주 얼굴/가림 영역의 의미 기반 분할, 표정·구조를 유지하는 편집 conditioning, cross-age 학습 목적, 사람 평가를 정리했다. 후속 평가에서는 연령 변화·identity·배경 보존·자연스러움을 함께 확인할 필요가 있다.

일부 초기 CPU 진단 스크립트 실패 로그와 별도 성공 재시도를 보존했다. 모델 추론 성공과 진단 스크립트 실패는 별도로 기록했다. 기존 데이터·모델·100/200/300 및 12-step 산출물도 그대로 보존했다.

아래는 당시 설정을 사용하는 재검사 예시이며 현재 실행 안내와 구분한다.

```bash
# 기존 산출물은 덮어쓰지 않는다. 재실행 시 새 output 경로를 지정한다.
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 OMP_NUM_THREADS=4 MKL_NUM_THREADS=4 TQDM_DISABLE=1 \
.venv/bin/python -m gen.compare_lora \
  --manifest outputs/age_lora_stages_20261026/preflight/manifest.json \
  --config outputs/age_lora_stages_20261026/recovery/config.json \
  --baseline \
  --checkpoint step100=outputs/age_lora_stages_20261026/train/checkpoint-100 \
  --insightface-reference --output outputs/age_lora_recovery_recheck
```
