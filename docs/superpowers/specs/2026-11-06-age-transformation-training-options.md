# 연령 변환 모델 학습 방법 비교 (2026-11-06)

이 문서는 연령 변환 모델을 **GPU로 학습하는 방법 8가지**를 비교합니다.

- 8가지 모두 **혼자서 메인 파이프라인이 될 수 있는 방법**만 골랐습니다. 다른 방법을 보조하는 용도나 비상 대체 수단은 넣지 않았습니다.
- 각 방법은 **데이터셋(기본 + 보충) / 모델 / 학습 방법 / 추론 방법** 순서로 정리했습니다.
- 보충 데이터셋은 기본 데이터셋으로 학습이 잘 안 될 때 추가하는 데이터입니다.

## 1. 현재 상태와 실패 원인

현재 구성은 Realistic Vision V5.1 (SD1.5) + IP-Adapter FaceID + 캡션으로 학습한 Age LoRA입니다. 아래는 고정 val 20장으로 측정한 결과입니다.

| 조건                                        | ArcFace       | 8세→80세 나이 변화 폭 |
| ------------------------------------------- | ------------- | --------------------- |
| FaceID만                                    | 0.633         | **15.65**             |
| LoRA 100 step                               | 0.688         | 5.60                  |
| LoRA 300 step                               | 0.691         | 5.79                  |
| 배경 보존 수정 후, FaceID만 / LoRA 100 step | 0.760 / 0.806 | 6.35 / 3.25           |

- **ArcFace**: 원본과 결과가 같은 사람처럼 보이는 정도입니다.
- **나이 변화 폭**: 같은 입력을 목표 나이 8세와 80세로 각각 바꾼 뒤, 두 결과를 InsightFace로 나이 추정해서 그 차이를 평균한 값입니다. 정확도가 아닌 참고값입니다.

LoRA를 학습할수록 ArcFace는 올라갔지만 나이 변화 폭은 줄었습니다. 원인은 세 가지로 봅니다.

1. **캡션 LoRA는 "편집"을 배우지 않았습니다.**
   - "a photo of a man in his 40s" 같은 캡션으로는 "40대 얼굴을 그리는 법"만 배웁니다.
   - 같은 사람의 변환 전/후 쌍이 없었기 때문에 "이 얼굴을 40대로 바꾸는 법"은 배울 수 없었습니다.
2. **원래 나이로 되돌리는 힘이 여러 곳에 있었습니다.**
   - FaceID 임베딩에는 원래 나이 정보도 섞여 있습니다.
   - img2img strength가 0.6이라 원본이 많이 남습니다.
   - 눈·입 보호 영역 때문에 눈가 주름 같은 나이 신호가 막혔습니다.
3. **학습할 때와 쓸 때의 조건이 달랐습니다.**
   - LoRA는 `train_text_to_image_lora.py`로 **FaceID 없이** 학습했습니다.
   - 그런데 추론할 때는 FaceID(IP scale 0.8)와 FaceID LoRA를 함께 썼습니다.
   - 다만 FaceID만으로 설명되지는 않습니다. **FaceID 조건이 똑같은 상태에서도** LoRA를 넣으면 나이 변화 폭이 15.65에서 5.6으로 줄었습니다.

그래서 8가지 방법은 모두 아래 원칙 중 하나 이상을 따릅니다.

- 같은 사람의 변환 전/후 쌍으로 학습한다.
- 나이 손실(우리 나이 추정 모델)과 얼굴 손실(ArcFace)을 직접 최적화한다.
- 얼굴을 유지하는 장치를 학습할 때도 추론할 때와 똑같이 켜 둔다.

## 2. 공통 사항

### 2.1 평가 프로토콜

- **평가 이미지**: 고정 val 20장 (`outputs/age_lora_stages_20261026/preflight/manifest.json`)
- **목표 나이**: 8 / 25 / 45 / 65 / 80
- **seed**: 42
- **측정 지표**
  - 나이 변화 폭 (8→80)
  - 목표 나이 순서대로 결과 나이가 단조 증가하는지
  - 목표 나이 대비 MAE
  - ArcFace
  - 얼굴 검출률
  - 1장당 생성 시간
- **나이 추정기 분리**: 학습할 때와 평가할 때 서로 다른 나이 추정기를 씁니다.
  - 학습 손실과 데이터 필터에는 팀의 MobileNet을 씁니다.
  - 평가 MAE는 InsightFace genderage로 계산합니다. MobileNet으로 잰 MAE는 참고값으로만 적습니다.
  - 이유: 학습에 쓴 추정기로 평가까지 하면, 모델이 그 추정기만 속이는 경우를 알아낼 수 없습니다.
- **test 100장**: 설정을 확정한 뒤 딱 한 번만 씁니다.

### 2.2 채택 기준

학습 전 베이스 모델(기준선)과 비교해서 아래 두 조건을 모두 만족해야 채택합니다.

- 나이 변화 폭과 MAE가 좋아진다.
- ArcFace와 얼굴 검출률이 떨어지지 않는다.

ArcFace만 오르고 나이 변화가 줄어든 경우는 채택하지 않습니다.

### 2.3 추론 공통 처리

```
원본 → 얼굴 검출·주 인물 선택 (gen/faces.py) → 얼굴 crop (방법별 정렬 방식)
     → [방법별 변환]
     → 원래 좌표로 되돌려 얼굴 마스크 영역만 합성 (preserve_background, 마스크 밖 픽셀 변화 0)
```

- 목표 나이는 현재 나이 a를 기준으로 a−10, a+10, a+20이며, [3, 90] 범위로 자릅니다.
- 눈·입 보호 영역은 줄입니다. 눈가 주름이 나이 표현의 핵심이기 때문입니다.
- 영수증 출력(58mm 384 dot, 80mm 576 dot) 기준으로 얼굴 한 칸은 약 300px이면 충분합니다. 그래서 GAN 계열의 256px 출력도 출력 품질에서 손해가 거의 없습니다.

### 2.5 쌍 데이터셋 P (M1, M2, M3, M7의 학습 데이터)

"같은 사람의 변환 전 / 변환 후" 쌍은 실제로 촬영할 수 없습니다. 그래서 학습 전에 한 번 생성해 두고 네 방법이 같이 씁니다.

- 형식: `(원본 얼굴, 원본 나이, 목표 나이, 결과 얼굴)`

| 구성              | 만드는 법                                                                                  | 특징                                            |
| ----------------- | ------------------------------------------------------------------------------------------ | ----------------------------------------------- |
| **P-SAM** (기본)  | FFHQ-Aging train 2,000장을 공개 SAM으로 5~85세(10살 간격)로 변환                           | 나이를 정확히 지정할 수 있고 구도가 원본과 같음 |
| **P-Edit** (기본) | 같은 입력을 베이스 편집 DiT(FLUX 3 Klein)로 변환한 뒤 seed 4개 중 가장 좋은 결과를 고름    | 사실적이고 화질이 높음                          |
| **P-Real** (보충) | AgeDB에서 같은 사람의 서로 다른 나이 사진을 5점 정렬해서 쌍으로 만듦. 부족하면 FG-NET 추가 | 실제로 늙은 사진이지만 포즈·조명 차이가 섞임    |

- **필터**: 아래 세 조건을 모두 만족하는 쌍만 남깁니다.
  - |MobileNet 추정 나이 − 목표 나이| ≤ 5 (목표가 65세 이상이면 ≤ 8)
  - ArcFace ≥ 0.6
  - 결과 이미지에서 얼굴이 검출됨
- **규모**: 필터를 통과한 쌍 1만 개 이상을 목표로 합니다. 반대 방향(늙은 얼굴 → 젊은 얼굴) 쌍도 같이 씁니다.
- **누수 방지**: val/test와 같은 인물이 들어가지 않도록 `audit_lora_split` 결과를 따릅니다.
- **보충 입력 얼굴**: 아동, 70세 이상, 아시아인 구간이 부족하면 AAF, MegaAge-Asian, CelebA-HQ 얼굴로 쌍을 더 만듭니다.

## 3. 방법별 정리

### M1. Age Adapter (편집 DiT + 숫자 나이 + 나이·얼굴 손실)

**쉬운 설명**: 그림을 잘 그리는 편집 모델에 "나이 숫자 다이얼"을 달아 줍니다. 학습할 때는 우리 나이 추정 모델과 ArcFace가 "나이가 맞는지, 같은 사람인지"를 직접 채점합니다.

**데이터셋**

- 기본: P-SAM + P-Edit
- 보충
  - 나이 정확도가 부족하면 P-SAM 비율을 높입니다.
  - 사실감이 부족하면 P-Edit 비율을 높입니다.
  - 실제 같은 노화 표현이 부족하면 P-Real(AgeDB)을 20% 이하로 섞습니다.
  - 아시아인 얼굴이 약하면 AAF, MegaAge-Asian 입력으로 쌍을 추가합니다.

**모델**

- 베이스: FLUX 3 Image Klein (5.6B, base 체크포인트). 학습 도구가 불안정하면 FLUX.1 Kontext dev로 바꿉니다.
- 나이 임베딩 모듈
  - (목표 나이, 원본 나이) → sinusoidal 인코딩 → 2층 MLP
  - 출력은 DiT의 timestep/pooled 변조 벡터에 더합니다(adaLN).
  - 마지막 층은 0으로 초기화합니다. 그래서 학습 시작 시점의 결과는 베이스 모델과 똑같습니다.
- attention 층에 LoRA (rank 32)
- 지시문은 고정 문장 하나만 씁니다 ("Change this person's age."). 나이는 숫자로만 조절합니다.

**학습 방법**

- 기본 손실: flow matching (속도 MSE). 원본 얼굴을 조건 이미지로 넣고 결과 얼굴을 정답으로 씁니다.
- 보조 손실: 노이즈가 적은 구간(t < 0.3)에서 4 step에 한 번만 계산합니다.
  1. 모델이 예측한 깨끗한 이미지 x̂₀를 VAE로 디코딩합니다.
  2. 나이 손실 = |MobileNet(x̂₀) − 목표 나이|. MobileNet 가중치는 고정합니다.
  3. 얼굴 손실 = 1 − cos(ArcFace(x̂₀), ArcFace(원본))
  4. 최종 손실 = flow + 0.05·나이 + 0.1·얼굴 (가중치는 이 값에서 시작해 조정)
- 학습률 1e-4 (나이 모듈은 1e-3)
- batch 1 + gradient accumulation 8, gradient checkpointing, bf16
- 3,000~6,000 step
- 학습 중 10%는 나이 조건을 비웁니다. 그래야 추론 때 CFG를 쓸 수 있습니다.
- **Ablation**: flow만 / +나이 / +얼굴 / 둘 다, 네 가지를 비교합니다.

**추론 방법**: 얼굴 crop + 현재 나이 a + 목표 나이 숫자를 넣고 8~16 step 생성합니다. 나이 효과의 강도는 CFG 1.5~3으로 조절합니다. 결과는 얼굴만 원본에 합성합니다.

**비용·위험**

- 쌍 데이터 생성 1~2일, 학습 1~2일 (24GB GPU)
- 모델이 MobileNet만 속이는 방향으로 학습될 위험이 있습니다. 나이 손실 가중치를 작게 두고, 평가는 InsightFace로 합니다.

### M2. 자기 증류 편집 LoRA

**쉬운 설명**: 편집 모델이 그린 결과 중에서 잘 된 것만 모아, 그것으로 다시 학습시킵니다. 나이는 문장으로 지정합니다.

**데이터셋**

- 기본: P-Edit (필터를 통과한 쌍 1~2천 개)
- 보충: 쌍이 부족한 목표 나이 구간은 P-SAM으로 채웁니다. 입력 얼굴은 AAF, MegaAge-Asian으로 늘립니다.

**모델**: FLUX 3 Klein (대안 FLUX.1 Kontext dev) + LoRA

**학습 방법**

- 학습 샘플: (원본, `"Make this person look {age} years old"`, 결과)
- rank 16~32, 학습률 1e-4, batch 1 + gradient accumulation 4, bf16, 1,000~3,000 step
- 손실: flow matching
- 도구: AI Toolkit 또는 diffusers. Klein용 설정 이름은 공식 예제로 확인해야 합니다.

**추론 방법**: 위 지시문 + LoRA(가중치 0.6~1.0)로 생성한 뒤 얼굴만 합성합니다.

**비용·위험**

- 2~3일
- 베이스 모델이 한 번도 만들어 내지 못한 변환(예: 유아 → 80세)은 쌍이 없어서 배울 수 없습니다.

### M3. FaceID를 켠 채로 학습하는 Age LoRA (기존 SD1.5 파이프라인 개선)

**쉬운 설명**: 지금 쓰는 파이프라인은 그대로 두고, 학습 방식만 고칩니다. 기존 방식은 "FaceID 없이, 짝 없는 사진"으로 학습했습니다. 새 방식은 "FaceID를 켜고, 변환 전/후 쌍"으로 학습합니다.

**데이터셋**

- 기본: P-SAM + P-Edit (512px로 맞춤)
- 보충: P-Real(AgeDB). 아동·노인 구간은 FG-NET, AAF 입력으로 쌍을 추가합니다.

**모델**: Realistic Vision V5.1 + IP-Adapter FaceID Plus v2 (고정) + Age LoRA (학습)

- 기존 `gen/pipeline.py` 구성을 그대로 씁니다.

**학습 방법** (diffusers 기본 스크립트 대신 직접 짠 학습 루프)

- 조건 입력은 **원본** 얼굴에서 뽑은 FaceID 임베딩, CLIP 이미지 임베딩, 그리고 목표 나이 캡션입니다.
- 정답은 **결과** 얼굴의 latent입니다. 손실은 노이즈 예측 MSE입니다.
- 추론 조건과 맞추기 위한 설정
  - timestep은 추론에서 쓰는 범위(t ≤ 0.6T, strength 0.6에 해당)에서 뽑습니다.
  - IP scale은 학습할 때마다 0.6~1.0에서 무작위로 정합니다.
- rank 16, 학습률 1e-4, 512px, fp16, 3,000~5,000 step
- RTX 4060 8GB에서도 batch 1이면 가능할 것으로 예상합니다. 현재 추론 메모리가 약 4GB입니다.

**추론 방법**: 현재 파이프라인과 같습니다 (img2img 또는 inpainting + FaceID + Age LoRA → 얼굴 합성).

**비용·위험**

- 2~3일
- 장점: 기존 코드와 평가 체계를 그대로 재사용합니다.
- 위험: SD1.5의 화질 한계는 그대로 남습니다.

### M4. SAM 재학습 (우리 나이 추정 모델을 나이 손실로 사용)

**쉬운 설명**: 나이 변환 전문 모델 SAM을 다시 학습시킵니다. 원래 SAM이 쓰던 나이 판정기를 우리 MobileNet으로 바꾸고, 아시아인 얼굴을 더 보여 줍니다.

**데이터셋**

- 기본: FFHQ-Aging train. 쌍이 필요 없고, 얼굴 사진만 있으면 됩니다.
- 보충: AAF, MegaAge-Asian(아시아인), CelebA-HQ. 아동 구간이 약하면 UTKFace를 추가합니다.

**모델**: SAM = pSp 인코더(학습) + StyleGAN2 FFHQ 생성기(고정). 공개 체크포인트에서 시작합니다.

**학습 방법**

- 입력: 얼굴 이미지 + 목표 나이 채널
- 손실 (SAM 원래 구성에서 나이 손실만 교체)
  - **나이 손실**: MobileNet(결과) vs 목표 나이 (원래는 DEX를 씀)
  - **얼굴 손실**: ArcFace
  - LPIPS, L2
  - w-norm
  - cycle 손실: 원래 나이로 다시 돌렸을 때 원본과 같아야 함
- batch 4~8, 공개 체크포인트에서 약 6만 iteration, 24GB GPU로 약 하루

**추론 방법**: FFHQ 방식으로 정렬 → SAM(목표 나이) → 1024px 얼굴 → 원래 좌표로 되돌려 합성

**비용·위험**

- 2~3일
- StyleGAN 특유의 흔적이 남을 수 있습니다.
- 역변환 단계에서 액세서리나 머리 모양이 바뀔 수 있습니다.

### M5. 짝 없는 데이터로 학습하는 조건부 GAN (StarGAN v2 / HRFAE 방식)

**쉬운 설명**: 연령 그룹별 사진 묶음만 보여 주고 "이 그룹 얼굴을 저 그룹 얼굴처럼 바꿔 봐"라고 학습시킵니다. 같은 사람의 전/후 쌍이 필요 없습니다.

**데이터셋**

- 기본: FFHQ-Aging train. 연령 그룹 10개를 6개 도메인(0–9, 10–19, 20–34, 35–49, 50–64, 65+)으로 묶어 씁니다.
- 보충: 사진이 적은 아동·65세 이상 도메인에 AAF, MegaAge-Asian, UTKFace를 추가합니다. 한국인 사용자 대응용으로 AFAD를 추가합니다.

**모델**: 조건부 생성기 1개 + 판별기 1개 (256px)

- StarGAN v2 방식: 도메인마다 스타일 코드를 둡니다.
- HRFAE 방식: 나이를 숫자로 받아 변조합니다.
- 숫자 나이로 조절하려면 HRFAE 방식을 고릅니다.

**학습 방법**

- 적대적 손실 (진짜 사진처럼 보이게)
- 나이 손실: MobileNet
- 얼굴 손실: ArcFace
- cycle 손실 (원래 나이로 되돌렸을 때 원본 복원)
- 1비트 흑백 출력이라 색 손실은 쓰지 않습니다.
- 약 10만 iteration, 24GB GPU로 1~2일

**추론 방법**: 정렬된 얼굴과 목표 나이를 넣고 한 번 순전파하면 끝납니다 (수 ms). 이후 얼굴만 합성합니다.

**비용·위험**

- 3~4일
- GAN 학습은 불안정할 수 있습니다 (mode collapse).
- 화질은 diffusion 계열보다 낮습니다. 다만 영수증 출력에서는 차이가 작습니다.

### M6. StyleGAN 잠재공간 나이 매퍼

**쉬운 설명**: StyleGAN의 얼굴 지도에서 "현재 위치 + 목표 나이"를 넣으면 "어느 쪽으로 얼마나 이동해야 하는지"를 알려 주는 작은 네트워크(매퍼)를 학습합니다.

**데이터셋**

- 기본: StyleGAN2로 무작위 생성한 얼굴의 잠재 벡터 w 5만 개. 실제 사진은 필요 없습니다.
- 보충: 생성 얼굴과 실제 사진의 분포 차이가 크면, FFHQ-Aging과 CelebA-HQ 사진을 e4e로 역변환한 w를 섞습니다. 아시아인 얼굴은 AAF를 역변환해서 추가합니다.

**모델**: StyleGAN2 FFHQ (고정) + e4e 역변환 인코더 (고정) + **나이 매퍼 MLP** (학습). 매퍼는 스타일 층마다 Δw = M(w, 목표 나이)를 출력합니다.

**학습 방법**

- 손실 = 나이 손실 (MobileNet(G(w+Δw)) vs 목표 나이) + 얼굴 손실 (ArcFace) + λ·‖Δw‖²
- ‖Δw‖² 항은 필요 이상으로 많이 바꾸지 않도록 하는 억제 항입니다.
- 약 2만 step, 몇 시간

**추론 방법**: 얼굴을 역변환해 w를 구함 → 매퍼로 Δw 계산 → 생성 → 얼굴만 합성

**비용·위험**

- 1~2일
- 학습이 가장 빠르고 가볍습니다.
- 품질은 역변환 정확도에 좌우됩니다. 액세서리나 아시아인 얼굴에서 약할 수 있습니다.
- M4보다 구조가 단순한 대신, 성능 상한도 낮습니다.

### M7. 나이 조건 작은 DiT를 처음부터 학습

**쉬운 설명**: 남이 만든 큰 모델을 빌리지 않고, 나이 변환만 하는 작은 생성 모델을 직접 설계해서 학습합니다.

**데이터셋**

- 기본: 쌍 데이터셋 P 전체 (1만 쌍 이상)
- 보충: 데이터가 부족하면 FFHQ-Aging train 전체로 P를 다시 만들어 늘리고, AAF 입력도 추가합니다.

**모델**: DiT-B/2 (약 1.3억 파라미터)

- 입력: 256px 얼굴 → VAE latent 32×32
- 공개된 DiT-XL/2-256 가중치에서 시작할 수도 있습니다. 이때 새로 늘어난 입력 채널은 0으로 초기화합니다.

**학습 방법**

- 입력: [노이즈 섞인 목표 latent ‖ 원본 latent]를 채널 방향으로 붙입니다.
- 나이 조건: 숫자 나이 → sinusoidal 인코딩 → MLP → timestep 임베딩에 더한 뒤 adaLN-Zero로 각 층에 전달합니다.
- 학습 중 10%는 조건을 비웁니다 (CFG용).
- 손실: flow matching + (선택) M1과 같은 나이·얼굴 보조 손실
- 약 10만 step, 24GB GPU로 반나절~하루

**추론 방법**: 4~16 step 생성 → VAE 디코딩 → 얼굴만 합성

**비용·위험**

- 3~5일
- 쌍을 만든 모델보다 품질이 낮을 수 있습니다.
- 결과가 흐릿해질 위험이 있습니다.

### M8. 나이 슬라이더 LoRA (Concept Sliders)

**쉬운 설명**: 사진 앱의 "나이 슬라이더 바"를 만드는 방법입니다. LoRA 가중치를 + 방향으로 주면 늙고, − 방향으로 주면 젊어집니다.

**데이터셋**

- 기본: 대조 프롬프트 쌍만 씁니다 ("person, old, wrinkles, gray hair" vs "person, young, smooth skin"). 이미지는 필요 없습니다.
- 보충: 효과가 약하면 이미지 쌍을 쓰는 방식으로 바꿉니다. FFHQ-Aging의 0~19세 그룹과 50세 이상 그룹을 대비시키고, 부족하면 CelebA-HQ `Young` 속성과 UTKFace를 씁니다.

**모델**: Realistic Vision V5.1 (SD1.5) + FaceID + 슬라이더 LoRA

- DiT에 적용하려면 AI Toolkit의 slider 기능이 해당 모델을 지원하는지 먼저 확인해야 합니다.

**학습 방법**

- 두 프롬프트(늙음 / 젊음)의 노이즈 예측 차이를 LoRA 하나에 담는 대조 학습입니다.
- FaceID를 켠 상태로 학습해서, 학습과 추론 조건을 맞춥니다 (M3과 같은 원칙).
- 500~1,000 step, 1~2시간

**추론 방법**

1. 슬라이더 가중치 w를 바꿔 가며 생성합니다.
2. MobileNet으로 결과 나이를 재서, w 1당 몇 살이 바뀌는지 직선으로 맞춥니다.
3. 목표 나이에 해당하는 w를 계산해서 생성합니다.
4. w의 상한은 ArcFace가 떨어지지 않는 범위로 정합니다.

**비용·위험**

- 하루
- w를 크게 주면 성별, 머리숱, 정체성까지 같이 바뀔 수 있습니다.

## 4. 비추천 방법

| 방법                                         | 이유                                                                                        |
| -------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 프롬프트 튜닝만 (학습 없음)                  | 직접 학습하는 결과물이 없습니다. 기준선 측정에만 씁니다                                     |
| 캡션 LoRA 재시도                             | 편집을 배우지 않는 구조입니다. 이미 실패를 확인했습니다 (나이 변화 폭 15.65 → 5.6)          |
| FaceID 없이 학습한 LoRA를 FaceID와 함께 사용 | 학습과 추론 조건이 달라 충돌합니다                                                          |
| SD3.5 + img2img + 얼굴 어댑터                | 텍스트→이미지 구조라 같은 실패가 반복됩니다. SD3.5용 얼굴 어댑터도 아직 미성숙합니다        |
| 전체 파인튜닝 (대형 모델)                    | 비용이 너무 큽니다                                                                          |
| 보상 기반 강화학습 (Flow-GRPO 등)            | 불안정하고 보상 해킹 위험이 있습니다. M1의 보조 손실이 같은 목적을 더 안정적으로 달성합니다 |
| 상용 API                                     | 사용자 얼굴을 외부로 보내야 하고, 직접 학습한 결과물이 없습니다                             |
| 개인화 노화 (SelfAge 등)                     | 한 사람의 여러 나이대 사진이 필요해서 부스 환경에 맞지 않습니다                             |

## 5. 필요 자원

- **나이 추정 모델 (MobileNet, 학습 완료)**: 모든 방법에서 나이 손실, 필터, 보정에 씁니다. 평가는 InsightFace로 따로 합니다 (2.1).
- **GPU 서버 (24GB 이상)**: P 생성, M1, M2, M4, M5, M7에 필요합니다.
- **RTX 4060 8GB로 가능한 것**: M3, M6, M8. 단, M3은 batch 1 기준입니다.
