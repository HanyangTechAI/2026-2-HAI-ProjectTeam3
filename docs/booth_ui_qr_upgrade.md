# 상대 연령 4컷과 사진·QR 자동 영수증

## 범위와 상태
- 사용자가 실제 촬영 사진의 나이 추정·FADING 4컷·화면 QR 생성 성공을 확인했다.
- 변경본은 별도의 설치 파일이다. 사용자 장치에 아직 적용하지 않았다.
- 사용자는 PR #3의 상대 연령 구성과, 4컷 사진·QR을 함께 자동 1회 인쇄하는 방식을 선택했다.
- PR #2/#3의 대기 → 카운트다운 → 처리 중 → 완료 흐름을 기존 자동 처리에 맞춰 반영했다. PR 자체를 병합하거나 GitHub에 올리지 않았다.
- Runpod은 추정 나이를 반올림해 10년 전·현재 원본·10년 후·20년 후로 구성한다. 편집 목표만 3~90세로 제한한다. 추정 24세의 예시는 14·24·34·44세다.
- 실제 과거·미래 얼굴 예측이 아니다. 높은 연령에서는 제한으로 편집 나이가 겹칠 수 있고 각 칸의 파일명은 별도로 유지한다.
- PR #3의 35단계·보정 상한 5회·self 0.70 설정을 사용한다. 새 구성의 실제 속도·외모 보존·연령 구분 품질은 사용자 환경에서 다시 확인해야 한다.
- 기존 촬영·좌우반전·원본 저장·원본 인쇄 함수 내용은 교체하지 않는다. PR의 처리·카메라 구현을 통째로 덮어쓰지 않는다.
- 성별 조건·전송 저장 동의·새로고침 복구·실제 연결 주소·QR 1시간 만료는 유지한다. 실제 사진 저장 완료까지 움직이지 말라는 표시를 유지한다.
- Runpod 응답에 초기·목표 연령과 작업 식별자가 없거나 목표가 요청 규칙과 다르면 인쇄하지 않는다. 예전 고정 연령 응답을 상대 연령 결과로 잘못 표시하지 않는다.
- 기존 원본 촬영·저장·인쇄 버튼은 접어둔 항목에서 사용할 수 있다.
- 다음 사람 촬영은 화면의 이전 작업·성별·동의 선택을 지운다. 사진 파일 삭제가 아니다.

## 사진·QR 인쇄
- 새 작업의 4컷·QR 생성 후 화면과 동일한 4컷 사진과 QR을 한 장에 자동으로 한 번 인쇄 요청한다. 다시 촬영하지 않는다. 이전 완료 작업을 열어도 인쇄하지 않는다.
- 기존 설정 `/dev/ttyACM0`, 115200 baud, 384픽셀 ESC/POS 래스터 전송을 사용한다.
- 사진은 기존 인쇄처럼 밝기·대비 조정 후 흑백으로 변환한다. QR은 그 뒤 정수 배율로 따로 붙여 사진 보정·디더링을 적용하지 않는다. 휴대전화에는 컬러 PNG를 제공한다.
- 한글 글꼴에 의존하지 않도록 종이의 짧은 안내는 영어다. 같은 와이파이·1시간 유효 안내를 넣었다.
- 기존 사진 인쇄와 QR의 전송이 섞이지 않도록 잠금을 사용한다.
- 전송 성공은 실제 종이 출력 성공을 증명하지 않는다. 용지와 휴대전화 스캔을 확인해야 한다.
- 실패·일부 전송·인쇄 중 재시작 시 자동 재인쇄하지 않는다. 일부가 이미 출력됐을 수 있다. 화면 QR과 다운로드는 유지한다.
- 새로고침·상태 조회는 프린터를 열지 않는다. 별도 수동 재인쇄 기능은 없다.

## 적용 순서
0. 앞서 전달한 QR 전용 `upgrade_booth_ui_qr.py`는 사용하지 않는다. 이미 실행했다면 새 설치기는 덮어쓰지 않고 중단하므로 그 내용을 먼저 알려준다.
1. 파일 탭에서 `upgrade_booth_relative_runpod.py`와 `upgrade_booth_relative_pi.py`를 받는다.
2. Runpod의 Jupyter에서 `/workspace` 폴더로 첫 번째 파일을 올린 뒤 새 터미널에서 실행한다. 실제 처리 창과 맥 SSH 연결은 아직 종료하지 않는다.

```bash
/workspace/fading-env/bin/python /workspace/upgrade_booth_relative_runpod.py
```

기존 코드가 검토한 버전과 다르거나 FADING 코드·가중치 연결이 없으면 중단한다. 검토된 코드이면 API와 생성 도구만 백업·교체하고 실제 모델·사진·가상환경은 건드리지 않는다. 연구용 `age/common.py`도 교체하지 않는다. 쓰기 실패 시 이 설치가 바꾼 코드 파일만 복원한다.

3. 준비 완료와 백업 경로를 확인하고, 촬영·생성이 진행 중이지 않을 때 기존 Runpod 처리 창에서 Ctrl+C로 종료한다. 그 창에서 같은 명령으로 다시 실행한다.

```bash
cd /workspace/age-photobooth
/workspace/fading-env/bin/python -u -m uvicorn app.fading_booth_api:app --host 127.0.0.1 --port 8000
```

다른 터미널에서 확인한다.

```bash
curl --max-time 15 http://127.0.0.1:8000/health
```

`target_offsets`가 `[-10,10,20]`인지 확인한다. 예전 `targets:[10,30,50]`이면 아직 예전 프로그램이다. 이 health만으로 실제 생성 성공을 판단하지 않는다.

4. Runpod 준비 후 맥에서 라즈베리파이용 파일을 복사한다.

```bash
scp ~/Downloads/upgrade_booth_relative_pi.py photobooth@photobooth.local:~/
```

5. 촬영·생성이 끝난 때 라즈베리파이 터미널에서 실행한다.

```bash
/home/photobooth/photobooth/env/bin/python ~/upgrade_booth_relative_pi.py
```

6. 백업 경로와 변경 준비 완료가 출력됐을 때만 적용한다.

```bash
sudo systemctl restart photobooth.service
curl --max-time 15 http://127.0.0.1:5000/api/booth/health
```

7. `hai_connected: true`를 확인하고 촬영 화면을 새로고침한다. 이름은 기존 점검과의 호환성을 위해 유지했다.
8. 어느 쪽이든 설치가 중단되면 프로그램을 재시작하거나 반복 설치하지 말고 출력 내용을 확인한다.

설치 파일은 기존 구조 검사 후 백업하고 교체한다. 중복 적용은 거부한다. 모델·사진·접속 통로는 바꾸지 않으며 설치 자체로 프린터를 작동하지 않는다.

## 현장 검증
1. 맥 SSH 연결 2개와 Runpod 처리 프로그램을 유지한다.
2. 동의하지 않으면 AI 촬영이 시작되지 않는지 확인한다.
3. 한 번 촬영하고 상대 연령 4컷·화면 QR·같은 사진이 있는 종이 QR이 모두 나오는지 확인한다. 화면·종이·다운로드의 사진이 같은 작업인지 확인한다.
4. 같은 와이파이 휴대전화로 종이 QR을 스캔하고 해당 작업 사진을 내려받는다.
5. 완료 화면 새로고침으로 종이가 추가 출력되지 않는지 확인한다.
6. 다음 사람 촬영에서 성별·동의가 초기화되는지 확인한다.
7. 기존 원본 촬영·저장·인쇄가 유지되는지 확인한다.
8. 프린터를 사용할 수 없는 상태에서도 새 작업의 화면 QR·다운로드가 유지되는지 확인한다.

합성 자료 자동 검사·모의 브라우저 검사는 실물 카메라·GPU·프린터 시험을 대신하지 않는다.

## 복구
라즈베리파이는 출력된 `app.py.before_ui_qr_...`가 변경 전 원본이다. 현재 파일도 별도 이름으로 보관한 뒤 해당 백업을 `app.py`로 복사하고 서비스를 재시작한다. Runpod은 `.booth_relative_backup_...`의 manifest와 백업이 복원 기준이다. 실제 출력된 경로를 보내주면 양쪽 복구를 안내한다. 다른 백업 이름을 추측하거나 사진 폴더를 지우지 않는다.
